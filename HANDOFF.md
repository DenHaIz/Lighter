# Lighter — handoff

Состояние на 29.10.2026, версия **1.1.1** (теги `v1.0.0`, `v1.1.0`, `v1.1.1`). Репозиторий: https://github.com/DenHaIz/Lighter.

## Что это

Менеджер автозагрузки Windows в одном `.exe` (~240 КБ). Источники:
- реестр Run/RunOnce, Policies\Run;
- папки «Автозагрузка»;
- задачи планировщика;
- службы с автозапуском;
- скрытые места: Winlogon, IFEO, Active Setup, BootExecute, AppInit_DLLs.

Читаются профили **всех пользователей ПК**. Для каждого файла проверяется **цифровая подпись**. Отдельная вкладка показывает процессы.

Действия: включить/выключить, удалить с резервной копией. Есть тёмная и светлая тема, RU/EN, плавные анимации.

## 1.1.1

- **Пиксельное перо в логотипе.**
  - Где задаётся: `Logo.Feather` — сетка 10×11, `#` — «пиксель» цвета знака, просветы по диагонали — стержень.
  - Как рисуется: одной фигурой (без швов между квадратами), по центру кольца.
  - Размеры: появляется от 24 px, в 16–20 px только кольцо — внутри слишком мало места.
  - PNG для README: `docs/logo.png` (128 px, `MakeIcon.exe x.ico --png <папка>` → `logo128.png`).
- **Столбцы снова можно растягивать.**
  - Причина: при любом изменении ширины `ListViewEx` заново раскладывал столбцы по пропорциям (`ColumnWeights`), и перетащенный разделитель отскакивал обратно.
  - Решение: заголовок присылает `HDN_BEGINTRACK` / `HDN_DIVIDERDBLCLICK` (`WM_NOTIFY` в `WndProc`). Получив его, список переходит на ручные ширины: пропорции выключаются, тянется только последний столбец.
  - Состояние у каждого из четырёх списков своё.
  - Отличать по флагу `fitting` нельзя: `ColumnWidthChanged` приходит и при создании окна списка. В DriveUP та же ошибка.
- Проверено:
  - перетаскивание разделителя на настоящем заголовке (сообщения мыши) — «Имя» 217 → 367 px, ширина держится, при растягивании окна растёт последний столбец, другие списки не затронуты;
  - значок во всех размерах через `LoadImage`, логотип в шапке.

## 1.1

- **Все пользователи ПК.** Администратор обычно запускает Lighter у чужой учётки, вводя свой пароль в UAC. Тогда HKCU и «Автозагрузка» — админские. Поэтому:
  - профили берутся из `HKLM\...\ProfileList` (SID `S-1-5-21-*` и `S-1-12-1-*`);
  - куст вошедшего пользователя — `HKEY_USERS\<SID>`;
  - куст не вошедшего — `RegLoadAppKey(NTUSER.DAT)`, только на время чтения или записи (`HiveRoot`, всегда `using`), иначе пользователь не сможет войти;
  - один куст открывается одним потоком за раз (блокировка по SID);
  - столбец и фильтр «Пользователь»: для задач — учётка запуска, для служб — учётка службы, для HKLM — «Для всех». Имена учёток приводятся к одному виду (`Accounts.Name`: SID / `NT AUTHORITY\…` / «СИСТЕМА» → `SYSTEM`).
- **Подпись** (`Signature.cs`) работает как в Autoruns:
  - сначала `WinVerifyTrust` по самому файлу;
  - если подписи нет — ищется системный каталог (`CryptCATAdmin*`: SHA-256, затем SHA-1) и проверяется сам `.cat`;
  - без интернета: отзыв не проверяется, только кэш URL;
  - кэш по файлу и по каталогу.

  Как результат попадает в интерфейс:
  - «Издатель (подпись)» — проверенный подписант или «Нет подписи · CompanyName»;
  - янтарная точка — нет действительной подписи;
  - фильтр-сегмент «Сторонние / Без подписи / Все».
- **Что считается системным:**
  - Run и «Автозагрузка» никогда не скрываются, как в Диспетчере задач;
  - службы, задачи и новые места скрываются, если подписаны Microsoft (`Microsoft Windows*` или `Microsoft Corporation`);
  - задачи — ещё и по папке `\Microsoft`.
- **Программы-запускалки** (rundll32, regsvr32, cmd, powershell, wscript, mshta…): проверяется файл из аргументов (`PathUtil.FileInArgs`). Если файла нет (`powershell -enc …`), запись всегда видна (`AlwaysShow`).
- **Новые места** (`ExtraLocations.cs`). Значение Windows по умолчанию — системное, его нельзя удалить. Всё остальное видно всегда. Удаление каждого места всегда начинается с `.reg`-копии:

  | Место | Что делает «удалить» |
  |---|---|
  | Winlogon `Shell` / `Userinit`, HKLM | возвращает значение Windows («Вернуть значение Windows») |
  | Winlogon `Shell`, HKCU пользователя | удаляет значение |
  | IFEO `Debugger` (64 и 32 бит) | удаляет `Debugger` |
  | Active Setup (64 и 32 бит) | удаляет `StubPath`; вкл/выкл через `IsInstalled` |
  | BootExecute | убирает строку (по умолчанию — `autocheck autochk [/ключи] *`) |
  | AppInit_DLLs | очищает значение; вкл/выкл через `LoadAppInit_DLLs` |

  - У Active Setup с `ShellComponent` вызывается эта DLL, поэтому проверяется она.
  - У Userinit проверяется то, что дописано рядом с `userinit.exe`.
- **Планировщик:**
  - задачи Microsoft — только «при входе / при загрузке»;
  - сторонние — с любым триггером;
  - задача, XML которой не читается, всё равно показывается («нет доступа к заданию»).
- **Оформление как в DriveUP** (`..\DriveUP`, тот же каркас; Lighter → Wisp Cleaner → DriveUP):
  - файлы каркаса взяты из DriveUP почти без изменений: `Anim`, `Transition`, `Controls`, `ListViewEx`, `Dialogs`, `TextDraw`, `Theme`, `Lang`, `Widgets` (без `Card` и `CategoryList`);
  - фиолетовый акцент `#8B5CF6`/`#7C3AED` (палитра прежней фиолетовой DriveUP);
  - контролы высотой 36, жирные значки вкладок;
  - интерфейс растёт вместе с окном (`Theme.Zoom`, до 1,6);
  - в узком окне кнопки теряют подписи справа налево, переключатель темы оставляет только значки;
  - заглушки-«мерцалки» на время первой загрузки.
- **Логотип**: тот же знак (кольцо + штрихи), но рисуется как в DriveUP — 4× с уменьшением (`Logo.Render`), плитка с градиентом, 17 размеров. В `.exe` кадры от 48 px хранятся как PNG (Windows их читает), поэтому exe весит 240 КБ вместо 416. `Logo.AppIcon` для окна берёт только DIB ≤ 64: `System.Drawing.Icon` PNG-кадры не понимает.
- Исправлено в `ListViewEx`, есть и в DriveUP: после уменьшения окна видимый список оставлял лишнюю горизонтальную полосу прокрутки. Теперь последний столбец «подталкивается».

## Сборка и релиз

- `build.cmd` собирает `bin\Lighter.exe` встроенным в Windows компилятором (`%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`); SDK и Visual Studio не нужны.
  - Сначала `tools\MakeIcon.cs` рисует `obj\app.ico` кодом из `src\Logo.cs`.
  - `obj\MakeIcon.exe x.ico --png <папка>` дополнительно сохраняет PNG.
- `build.cmd dev` дополнительно собирает `bin\Lighter.dev.exe` с `asInvoker` — без UAC, для проверки интерфейса.
- Релиз:
  1. Поднять версию в `src\AssemblyInfo.cs` и закоммитить.
  2. (по желанию) Положить заметки в `.github\notes\vX.Y.Z.md`.
  3. `git tag vX.Y.Z` → `git push origin vX.Y.Z`.

  Workflow `.github/workflows/release.yml` соберёт exe и создаст GitHub Release с `Lighter.exe` и `.sha256`. Без файла заметок они генерируются из коммитов.
- Журнал кадров: `set LIGHTER_FRAMELOG=C:\путь\frames.log`. Строки:
  - `F время опоздание работа твинов` — кадр;
  - `T …` — переход: «до», «смена», «после».

## Что проверено, а что нет

Проверено (сессия без прав администратора, Windows Server 2022, RU):
- **Загрузка источников:**
  - свой профиль читается, чужие без прав корректно пропускаются;
  - загрузка, запись и выгрузка NTUSER.DAT — на тестовом кусте (чтение, отключение, удаление, файл освобождается, параллельные открытия);
  - подпись: встроенная, каталожная (`kernel32.dll` → Microsoft Windows), без подписи (скрипт, `nssm.exe`);
  - новые места: чтение и классификация на этой машине; удаление Policies\Run и пользовательского Winlogon Shell — на тестовом кусте;
  - время загрузки с подписями: реестр ~0,3 с, службы ~0,7 с (источники грузятся параллельно).
- **Интерфейс** (`Lighter.dev.exe`, снимки):
  - все вкладки, фильтры, светлая тема, EN;
  - окно 1700×1000 (масштаб) и минимальное 980×620 (подписи кнопок свёрнуты);
  - меню пользователей.
- **Плавность** (RDP, 1180×720; вкладки, фильтры, тема, язык, масштаб): интервал кадров p95 16,7 мс, работа кадра p95 ~7 мс. Первое открытие «Процессов» (~800 строк) — ~130 мс подготовки перехода, один раз.

**Не проверено:**
- От администратора: профили других пользователей на живой системе, запись в HKLM (Winlogon, IFEO, Active Setup, BootExecute, AppInit), вкл/выкл задач и служб.
- Анимации глазами на живом экране (снимки статичны).
- Окна подтверждения (взяты из DriveUP как есть).
- Прогон GitHub Actions для `v1.1.0`.

| `ExtraLocations.cs` | Winlogon, IFEO, Active Setup, BootExecute, AppInit_DLLs |
| `StartupFolderSource.cs` | Общая папка «Автозагрузка» и папка каждого пользователя, `.lnk` через WScript.Shell |

| `Com.cs` / `Native.cs` / `PathUtil.cs` | Позднее связывание COM, P/Invoke, разбор командной строки и аргументов |

| `Logo.cs` | Знак (кольцо и штрихи, фиолетовый на тёмно-сером), растр 4×, `.ico` |

## Решения и причины

- **.NET Framework 4.8 + встроенный csc** — один exe без установки на любой Windows 10/11/Server 2016+. Цена: синтаксис **C# 5** (нет `$""`, `?.`, `nameof`, expression-bodied членов).
- **Без `dynamic`** — он тянет Microsoft.CSharp и DLR; COM через `Com.cs`.
- **Общий каркас с DriveUP.** Исправления в `Anim`/`Transition`/`Controls`/`ListViewEx` лучше переносить в обе программы. Отличия Lighter: палитра, `Settings` в реестре, `Widgets` без лишнего, поправка полосы прокрутки в `ListViewEx`.
- **Вкл/выкл через StartupApproved** — обратимо и совпадает с Диспетчером задач. RunOnce и Policies\Run переключить нельзя, только удалить.
- **Службы не удаляются**, только отключаются. **Winlogon в HKLM не удаляется** — возвращается значение Windows.
- **Списки не докуются**, размер задаётся вручную всем, включая скрытые: докинг пропускает скрытые контролы.
- **Ленивая отрисовка**: перестраивается только видимый список, остальные помечаются `dirty`.
- **Загрузка параллельная**: каждый источник в своём STA-потоке, подписи — там же (до 4 файлов параллельно).
- **Резервная копия чужого HKCU** пишется как `HKEY_USERS\<SID>\…`. Двойной щелчок её восстановит, пока пользователь в системе.

## Подводные камни

- Глифы Segoe MDL2 в старом коде были записаны реальными символами Private Use Area. В `MainForm` теперь `\uXXXX` — так и держать.
- Снимки для переходов делаются через `WM_PRINT`. Всё, что рисуется только в `WM_PAINT`, нужно рисовать и в `WM_PRINTCLIENT`.
- Без прав администратора часть путей служб и процессов не читается (красная строка «файл не найден») — это не ошибка.
- PowerShell 5.1 пишет UTF-8 с BOM: сообщения коммитов из файла сохранять без BOM. В python-скриптах правки — raw-строки, иначе `\a`/`\L` в путях портятся.
- Git Credential Manager в неинтерактивной среде (`GCM_INTERACTIVE=never`) не покажет окно входа — для `git push` нужна интерактивная сессия.
- `System.Drawing.Icon` не читает PNG-кадры. Shell и `LoadImage` читают их без проблем.

## Как проверять

1. `build.cmd` (или `build.cmd dev`) — без ошибок.
2. От администратора, на тестовых записях:
   - `reg add HKCU\Software\Microsoft\Windows\CurrentVersion\Run /v LighterTest /d notepad.exe`
   - ярлык на notepad в `shell:startup`; то же у другого пользователя (вошедшего и не вошедшего) — запись видна с его именем
   - `reg add "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\lightertest.exe" /v Debugger /d notepad.exe`
   - `schtasks /create /tn LighterTest /tr notepad.exe /sc daily /st 09:00` (сторонняя задача по расписанию)
   - `sc create LighterTestSvc binPath= C:\Windows\notepad.exe start= auto`

   Проверить вкл/выкл/удаление, совпадение с Диспетчером задач / `schtasks /query` / `sc qc` и копии в Backup.
3. Фильтры «Сторонние / Без подписи / Все» и «Пользователь», поиск, F5, Ctrl+A, Space, Del. Переключение вкладок, тем и языка — без мигания. Растянуть окно — интерфейс крупнеет.
4. Удалить тестовые записи (`sc delete LighterTestSvc` и т. д.).
